### Under the Hood: The Client-Side Rendering Pipeline

Building an editor that handles multi-layer composition, 3D CSS transforms, and 8K rasterization without server lag required careful architectural discipline.

<Callout type="info">
  **The Zero-Upload Guarantee:** All image decoding, canvas manipulation, color extraction, and video rendering happen entirely inside the browser's execution thread and WebGL context. Your proprietary designs, unreleased feature screenshots, and sensitive customer data never touch a remote server.
</Callout>

```typescript
[User Drops Screenshot]
          │
          ├─ Decode in-memory via OffscreenCanvas / ImageBitmap
          ├─ Color Quantization: Extract dominant palette via Canvas 2D
          │
[Interactive Editor Canvas]
          │
          ├─ Reactive state management via Zustand (single store, zero re-render lag)
          ├─ CSS Custom Property tokens driving real-time layout & 3D matrices
          ├─ Procedural SVG backdrop generator (Mesh & Aurora gradient filters)
          │
[Export Stage]
          │
          ├── Static Image: High-DPI DOM clone rasterization → 8K PNG/WebP
          └── Video Clip:   RequestAnimationFrame tick → Frame buffer capture → WebCodecs / Canvas MP4 muxer
```

#### 1. Real-Time CSS Token Architecture

Instead of re-rendering heavy canvas bitmaps on every slider drag, the preview viewport relies on lightweight **CSS custom properties**. Moving a shadow slider or rotating the 3D tilt simply mutates CSS variables on the root container, keeping interactions at a silky **60 FPS** on both high-end desktops and mobile browsers.

#### 2. Frame-by-Frame Browser Video Rendering

Traditional video export in web apps relies on heavy server-side ffmpeg clusters. PrettyShot steps through its animation timeline keyframes sequentially, captures each rendered DOM state to an offscreen frame buffer, and encodes the stream directly using browser Web APIs. You get crisp 60fps MP4/WebM videos without queued cloud render times - and without your footage ever leaving the tab.
